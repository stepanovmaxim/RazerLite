# RazerLite

Крошечная утилита в трее для мышей Razer — замена Razer Synapse. Один процесс
на ~12 МБ и 42 КБ на диске вместо девяти процессов `RazerAppEngine`, службы
Game Manager и службы Elevation.

Умеет то, ради чего Synapse обычно и держат:

* **ступени DPI** — переключение, редактирование значений, изменение количества;
* **экранный индикатор DPI** — всплывающая плашка при смене ступени, в том числе
  когда ступень переключили кнопкой на самой мыши;
* **переназначение любых кнопок** — включая те, которых Windows вообще не видит
  (DPI, профиль, снайперская): клики, DPI, медиаклавиши, сочетания клавиш;
* **предупреждение о низком заряде** — оверлеем на экране;
* **частота опроса** — 125 / 250 / 500 / 1000 Гц;
* **таймер засыпания** беспроводной мыши;
* **заряд батареи** в подсказке трея;
* автозапуск, работа из командной строки.

Настройки пишутся в саму мышь (onboard-память), поэтому DPI и частота опроса
сохраняются, даже если утилита не запущена.

## Установка

```
build.cmd
```

Нужны Visual Studio Build Tools с рабочей нагрузкой «Разработка классических
приложений на C++» и Windows SDK. Сборка идёт без CRT (`/NODEFAULTLIB`),
результат — один `RazerLite.exe` без зависимостей.

Иконка перерисовывается скриптом `tools\make-icon.ps1` (запускать не обязательно,
`icon.ico` уже лежит в репозитории).

Скрипты в `tools\` сохранены в UTF-8 **с BOM**: без него Windows PowerShell
читает их как ANSI и ломается на кириллице.

## Использование

Запустите `RazerLite.exe` — в трее появится зелёная мышь, та же иконка, что у
самой программы.

* **левый клик** — следующая ступень DPI;
* **правый клик** — меню: DPI, частота опроса, засыпание, кнопки, устройство,
  автозапуск.

Значок — одна и та же картинка в трёх состояниях: обычный, **серый** когда мышь
не найдена, **красный** когда заряд упал ниже порога предупреждения. Текущие DPI
и заряд показываются в подсказке при наведении.

### Командная строка

| Ключ | Действие |
| --- | --- |
| `--dpi-next` | следующая ступень DPI |
| `--dpi-prev` | предыдущая ступень |
| `--status` | записать состояние в `%TEMP%\RazerLite-status.txt` |
| `--test-osd` | показать оверлей заряда, чтобы проверить его вид |
| `--reset-buttons` | вернуть всем кнопкам поведение по умолчанию |
| `--check-update` | проверить обновление прямо сейчас |
| `--exit` | закрыть работающую копию |

Команда, отданная при уже запущенной утилите, передаётся ей — так можно повесить
переключение DPI на горячую клавишу через ярлык.

### Переназначение кнопок

Меню → **Buttons** → нужная кнопка → действие.

Кнопки мыши Razer расходятся по двум разным путям, и утилита работает с обоими:

**Обычные кнопки** — левая, правая, колесо и две боковые. Они доходят до Windows
как обычные события мыши, поэтому перехватываются низкоуровневым хуком: старое
действие подавляется, вместо него выполняется назначенное. В меню они есть
всегда.

**Вендорные кнопки** — DPI, профиль, снайперская, клавиатурный блок у Naga.
Windows их не видит совсем: в driver-режиме мышь рапортует о них по вендорной
HID-коллекции. Подавлять там нечего — на эти нажатия всё равно никто не
реагирует, — поэтому назначение просто добавляет действие.

Список вендорных кнопок нигде не зашит: **нажмите кнопку, и она появится в меню**
сама. Утилита запоминает увиденные коды, а ту кнопку, после которой менялся DPI,
подписывает «DPI button».

Вендорная кнопка принадлежит той связи, на которой её увидели, и в меню
показывается только там. Коды DPI-кнопки с донгла (`20`/`21`) по Bluetooth не
существуют — там мышь переключает DPI сама и наружу об этом сообщает только
готовым значением, перехватывать нечего. Поэтому на Bluetooth в списке кнопок их
не будет, а вместо них — пояснение.

Коды `0x20` и `0x21` — это фирменные сигналы Razer «DPI вверх» и «DPI вниз»;
им сразу назначаются соответствующие действия, чтобы кнопка DPI заработала как
при Synapse. Мышь сама решает, вверх или вниз, и разворачивается на краю
диапазона. Если хочется, чтобы каждое нажатие шло по кругу только вперёд —
назначьте обеим «DPI: next stage».

### Кто обрабатывает DPI-кнопку

В меню **Buttons** есть флажок **«Let RazerLite handle the DPI button»**.

Мышь пересылает свои собственные кнопки драйверу, только если переведена в
driver-режим; предоставленная себе, она обрабатывает их сама, и переназначать
там нечего. Флажок и переключает это состояние, а заодно запоминает выбор и
восстанавливает его при каждом подключении — мышь забывает режим, как только
теряет питание. Снятый флажок возвращает мышь в onboard-режим, где DPI-кнопка
работает без запущенной утилиты.

Раньше на этом месте было меню Advanced с пунктами про device mode 0x00/0x03 —
то же самое, но словами протокола вместо смысла.

Прочее:

* хук ставится лишь тогда, когда переназначена хотя бы одна обычная кнопка —
  иначе утилита в поток ввода не вмешивается вовсе;
* назначения действуют, пока утилита запущена (в самой мыши они не сохраняются);
* если переназначить левую кнопку и остаться без кликов, спасёт
  `RazerLite.exe --reset-buttons`.

Чего пока нет: у моделей вроде Naga боковой блок в onboard-режиме шлёт не
вендорные отчёты, а настоящие нажатия клавиш (1…9, 0, −, =). Перехватить их
можно только клавиатурным хуком, а он не отличит эти клавиши от нажатых на
клавиатуре — для такого нужно связывать Raw Input с хуком по устройству. Если
понадобится, делается отдельно.

### Предупреждение о низком заряде

Меню → **Low battery warning** → порог (**5** / 10 / 15 / 20 / 25 % или
выключено, по умолчанию 20 %). Когда заряд опускается ниже, поверх экрана
появляется плашка с процентом и шкалой. Повторяется не чаще раза в полчаса и
дополнительно при каждом падении ещё на 5 %. Предупреждение выдаётся только по
свежему показанию: у спящей мыши значение остаётся прошлым, а она всё равно не
разряжается.

Ступень 5 % — для тех, кому напоминание на 20 % мешает: предупреждение приходит
один раз, уже перед самой заменой батареи. Значок в трее краснеет по тому же
порогу.

## Обновление

Меню → **Updates**. Рядом с названием пункта показана текущая версия.

* **Check now** — спросить GitHub прямо сейчас;
* **Install new versions automatically** (по умолчанию включено) — проверка
  через полминуты после запуска и дальше каждые 6 часов.

Утилита читает последний релиз через `api.github.com`, сравнивает тег с
собственной версией и, если на GitHub новее, скачивает приложенный
`RazerLite.exe`. Загруженный файл принимается, только если он начинается с `MZ`
и весит больше 16 КБ, — страница с ошибкой вместо программы запущена не будет.

Замена происходит без отдельного установщика: работающий exe перезаписать
нельзя, но **переименовать можно**. Старая сборка отходит в сторону как
`RazerLite.exe.old`, новая занимает её путь — поэтому автозапуск, ярлыки и
единственность экземпляра продолжают работать, — запускается с ключом
`--updated=<pid>`, дожидается выхода предшественника и показывает всплывающее
уведомление. Файл `.old` удаляется при следующем запуске.

Если автообновление выключено, утилита в сеть не ходит вообще: проверка
выполняется только по команде.

Релизы собираются на GitHub Actions: пуш тега `v*` запускает сборку и
прикладывает `RazerLite.exe` к релизу. Этот же файл и скачивает обновление.

## Две связи: донгл и Bluetooth

Мышь, умеющая и HyperSpeed, и Bluetooth, — это для Windows два разных
устройства, и утилита рассчитана на обе связи:

* устройство опознаётся по HID-атрибутам (VID/PID), а не по строке пути,
  поэтому находится одинаково при любой связи;
* **в пути идентификатор пишется по-разному**: USB — `VID_1532`, Bluetooth —
  `VID&00021532` плюс GUID BLE-службы. Уведомления о подключении фильтруются по
  обеим формам, иначе появление мыши по Bluetooth осталось бы незамеченным;
* при воткнутом донгле и мыши на Bluetooth видны **оба** устройства, и
  надёжного признака «эта связь активна» у Windows нет: BLE-устройство остаётся
  в списке и после разрыва, а `AlwaysShowDeviceAsConnected` у него вообще
  выставлен в True. Зато есть точный тест: **приёмник отвечает на команды
  только пока мышь подключена именно к нему** — если мышь ушла на Bluetooth,
  донгл отвечает таймаутом на всё. Утилита раз в 10 секунд задаёт донглу один
  вопрос и по ответу определяет связь;
* спящая на донгле мышь выглядит так же, как ушедшая на Bluetooth, поэтому
  переключение на BLE происходит только после трёх минут молчания донгла —
  иначе засыпание мыши каждый раз переключало бы связь;
* дополнительно утилита слушает HID-отчёты обеих связей: пришёл отчёт по
  Bluetooth — значит мышь там, и связь меняется сразу, не дожидаясь опроса;
* в меню **Device** связь подписана: у Bluetooth-устройства к имени добавляется
  `(Bluetooth)`, в `--status` есть строка `link`.

### Что работает по Bluetooth

Проверено на DeathAdder V2 X HyperSpeed: **по BLE вендорного протокола Razer
нет вообще** — ни одной коллекции с feature-отчётом в 91 байт. Настройками по
этой связи Synapse управлял не через HID, а через собственную GATT-службу
(`52401523-F97C-7F90-0E7F-6C6F4E36DB1C`), которая не документирована.

Поэтому по Bluetooth:

| | донгл | Bluetooth |
| --- | --- | --- |
| ступени DPI, частота опроса, таймер сна | да | **нет** |
| текущий DPI и плашка при смене | да | **да** |
| заряд и предупреждение о разряде | да | **да** |
| переназначение обычных кнопок | да | да |
| переназначение DPI-кнопки | да | **нет** (она работает сама) |

Два места, которые это вытягивают:

* **заряд** Windows сама читает из стандартной GATT-службы батареи и публикует
  свойством устройства `{104EA319-6EE2-4701-BD47-8DDBF425BBE5},2` — спрашивать
  мышь не нужно;
* **DPI** мышь по BLE объявляет сама: при нажатии своей DPI-кнопки она шлёт
  отчёт `05 05 02 <X hi> <X lo> <Y hi> <Y lo>`. Ступень она переключает
  самостоятельно, а утилита ловит это значение и показывает плашку.

Опознаётся мышь по фирменной GATT-службе Razer, а не по вендору: по BLE
DeathAdder V2 X сообщает `VID 068E / PID 009D`, а не Razer-овский `1532`, так
что фильтр по вендору такую мышь не нашёл бы.

Проверить свою мышь на конкретной связи:

```
powershell -ExecutionPolicy Bypass -File tools\probe-link.ps1
```

Скрипт печатает все HID-коллекции, находит управляющую, подбирает transaction id
и читает DPI, ступени и заряд.

## Другие мыши Razer

Ничего дописывать не нужно — модель нигде не зашита:

* берётся любое устройство с VID `1532`, у которого есть HID-коллекция с
  feature-отчётом в 91 байт;
* transaction id подбирается перебором (`0x1F`, `0x3F`, `0x08`, `0x00`, `0x9F`,
  `0xFF`) — беспроводные модели обычно отвечают на `0x1F`, проводные на `0x00`;
* имя читается из HID product string;
* возможности выясняются опросом: команда, на которую мышь ответила статусом
  `0x05` («не поддерживается»), просто не появляется в меню. Например, у
  DeathAdder V2 X HyperSpeed нет статуса зарядки и порога низкого заряда —
  соответствующих пунктов не будет.

Единственное место с перечнем моделей — `RzMaxDpiFor()` в `razer.h`: потолок DPI
для лестницы значений в меню. Для неизвестной модели берётся 16000, и мышь сама
отбросит недопустимое значение.

Если подключено несколько устройств Razer, в меню появляется пункт **Device**.

## Протокол

Razer принимает 90-байтный вендорный отчёт через HID feature report (report id 0)
на одной из своих коллекций. Проверено на DeathAdder V2 X HyperSpeed (PID `009C`):

| Команда | class/id | Результат |
| --- | --- | --- |
| версия прошивки | `00/81` | 1.0 |
| серийный номер | `00/82` | 22 байта ASCII |
| режим устройства | `00/84`, `00/04` | `0x00` onboard, `0x03` driver |
| частота опроса | `00/85`, `00/05` | 1 = 1000 Гц, 2 = 500, 4 = 250, 8 = 125 |
| DPI | `04/85`, `04/05` | X и Y, big endian |
| ступени DPI | `04/86`, `04/06` | активная + до 5 ступеней по 7 байт |
| заряд | `07/80` | 0..255 |
| таймер сна | `07/83`, `07/03` | секунды, big endian |

Контрольная сумма — XOR байтов 2..87 отчёта.

Полезные наблюдения:

* **Спящая мышь отвечает статусом `0x04`** на всё, хотя транспорт исправен:
  отвечает приёмник, а не мышь. Поэтому устройство, найденное спящим, считается
  присутствующим, а список возможностей допрашивается позже, когда мышь
  проснётся. Иначе утилита, запущенная при входе в систему, решила бы, что мыши
  нет.
* Запись DPI без сохранения (`varstore = 0x00`) при работающем Synapse не
  применяется — Synapse возвращает своё. Утилита пишет с `varstore = 0x01`, в
  onboard-память, и это работает при любом Synapse.
* Мышь и клавиатурные HID-коллекции открыть на чтение нельзя (ошибка 5) — их
  монопольно держит подсистема ввода. Вендорные коллекции открываются свободно,
  и по отчётам из них утилита узнаёт о нажатиях кнопок на мыши.
* На DeathAdder V2 X HyperSpeed кнопка DPI шлёт только вендорный отчёт
  (`04 20` / `04 21` на `MI_01/COL05`) и **сама ступень не меняет**: в
  driver-режиме этим занимается драйвер. Левая, правая, колесо и обе боковые,
  наоборот, приходят обычными событиями мыши и в вендорной коллекции не
  дублируются — то есть двойного срабатывания при переназначении не будет.

## Уход от Synapse

1. Убедитесь, что RazerLite видит мышь: `--status`.
2. Удалите Razer Synapse обычным способом.
3. Меню → **Advanced** → **Onboard mode** — переводит мышь в режим `0x00`, в
   котором она обрабатывает кнопку DPI сама, без драйвера.

Пока Synapse запущен, обе программы пишут в одну мышь, и настройки могут
конфликтовать — в меню на этот случай выводится предупреждение.

## Опрос устройства и батарея

Утилита опрашивает мышь только когда за компьютером работают: DPI — раз в 2 с,
заряд — раз в минуту. После минуты без ввода опрос прекращается полностью, чтобы
беспроводная мышь могла заснуть. Кроме того, утилита слушает вендорные
HID-коллекции: нажатие кнопки на мыши сразу вызывает перечитывание DPI, и плашка
появляется без задержки.

## Диагностика

`RazerLite.exe --status` → `%TEMP%\RazerLite-status.txt`: найденное устройство,
все прочитанные значения, список возможностей, назначения кнопок, обнаруженные
вендорные коды и состояние хука.

Последняя строка — счётчики опроса: сколько было тактов, чтений заряда и
предупреждений и сколько миллисекунд назад был последний ввод. По ней видно,
почему опрос «стоит»: после минуты без ввода он и должен останавливаться.

`RazerLite.exe --test-osd` показывает оверлей заряда, не дожидаясь разрядки.

Обратите внимание: оверлей — layered-окно, и обычный скриншот через GDI
(`CopyFromScreen`) его не захватывает, хотя на экране он виден.
